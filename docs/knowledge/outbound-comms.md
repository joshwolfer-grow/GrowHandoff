## Daily manager card (texted 9am): RETIRED Oct 14 2026

**Status:** the `com.wolfoffice.mgrcards` worker (and `payaudit`) was unloaded Oct 14 2026 (plist in `~/Library/LaunchAgents/disabled-grow/`). It had failed silently since Sep 25 because the `GROW_ACCESS_CODE` in `RepText/.env` was no longer in `access_codes` (the only active corporate code is named "Admin"), and no `Daily Report: <Manager>` Messages groups were ever created, so even a good run sent 0 cards. Everything below describes how it worked, in case it is revived (valid code in that .env, groups made by hand, worker reinstalled, Mac awake and unlocked at 9am).

- Card = `buildManagerReportImage` in `index.html`: black/white scoreboard matching the logo, 700px, canvas-safe fonts. Only two blocks by request: **yesterday** (reps + TEAM) and **week so far** (reps + TEAM). Content is Bria + knocking + booking only; goals, training, notes, flags and missing deals were removed. **Sold is Bria only** (yesterday and week; `_mgrWeekSales(...,briaOnly)` 4th arg, image builder only); knocking gives doors/contacts/time. BOOK column = Bria sale_date → install_date. Team membership (repSet) decides rows, not Df 'm' (report rows arrive 'Unassigned').
- Number rules baked in (Sep 11 2026): rep PRA = sold ÷ days worked over `PRA_MIN_KNOCKS`, clipped at `_kwCovThru` (not `_kwSalesThru`); Days / doors per day / close in the week block come from the same worked days so Sold ÷ Days = printed PRA; AVG row prints TEAM totals; knocking deduped rep|date; when yesterday's sold exceeds what feeds carry the header says "N from yesterday not counted yet". Verified example: Jake Hogue week 28 = 28/7 = 4.00 (weeks Sunday anchored).
- Job: `scripts/daily-report-text.mjs` drives the REAL app headless (Playwright, channel chrome) with `?code=<corporate access code>` from `RepText/.env`, calls `window._buildMgrCard` (exported because the builder is inside bootDashboard scope), writes a PNG per manager to `~/Pictures/GrowReports/`, then texts the Messages group named exactly `Daily Report: <Manager>`. `--scheduled --send` for the real run, `--to +1...` sends all cards to one number as a test, `--url` points at a local copy.
- Scheduler (until Oct 14 2026): WolfOffice worker `mgrcards` (WolfOffice workers.json, office_agents row, help.js, migration 0008) ran daily 09:00 via launchd. Only managers whose team had doors yesterday get a card; managers without a group are skipped and counted in the last log line.
- **Messages constraints:** scripts cannot create group chats; each group is made by hand once, found by display name in `~/Library/Messages/chat.db` and sent to by guid (members read from chat.db, card pasted via `paste-group.applescript`, confirmed by the attachment landing in that chat). Images must be copied into `~/Pictures` first or Messages drops them silently. Reading chat.db needs Full Disk Access. Background jobs (launchd, office-serve) get error -1743 on System Events, so any `--send` outside Terminal re-runs itself in Terminal via `open -a Terminal <.command>` and waits on a `.done` file in `~/Pictures/GrowReports/.run`. Terminal holds the permissions (granted Sep 16 2026). The Mac must be awake and unlocked at 9am. SMS relay reaches Android reps. Texts go from the Mac owner's own number (no texting service).
- `RepText/` tools: `groups.py` (`--list`, `--send NAME "msg" --image`), `send-chat.applescript`, `send_test.py` + `send.applescript` (per-number bulk; pace 10 to 15s apart, 500 texts ≈ 1.5 to 2 h). AppleScript form: `send msg to participant "+1..." of (1st account whose service type = iMessage|SMS)`.
- Open as of Sep 16: not all groups created, Full Disk Access/Accessibility for launchd node+osascript untested, the first `--send` run is a human step. Moving to a new Mac/number means recreating groups and permissions.

## Weekly rep email / snapshot (`api/weekly-rep-email.js`)

- Per-rep weekly recap (last completed Sunday week, two-week view). **Manual send only, no cron** (owner's call Jul 21 2026). Sends via Gmail SMTP (`nodemailer`, smtp.gmail.com:465, pooled) with `GMAIL_USER` + `GMAIL_APP_PASSWORD` (Workspace app password; the owner once hit "App Password not available"); optional `EMAIL_FROM` (authed account or a send-as alias); `EMAIL_DASH_URL`/`DASH_URL`. ~131 emails/week is far under the Workspace limit. (The memory index once said "pending Resend key"; Gmail SMTP is what was built.)
- Modes: GET with key = control panel (eligible count, preview, Send to all via POST); `?render=1[&rep=Name]` preview; `?test=addr` one sample; `?json=1` / `?dry=1` JSON; `?send=1&rep=Name` one; POST `{reps:[...]}` subset; `?send=1&rep=Name&to=email` manual address; `?knocking=1` / POST `knockOn:[...]` per-team knocking toggle; `?corp=1` corporate recap preview, `POST ?corp=1&send=1` with a `to` list; `?snapshot=<rep>[&weeks=1|2|4|8]` unauthenticated render-only snapshot (CDN `s-maxage=600, stale-while-revalidate`). Auth: `EMAIL_ADMIN_KEY` first, then CRON_SECRET/SYNC_TRIGGER_KEY, as Bearer or `?key=`.
- **Snapshot = the canonical per-rep view** (Jul 30 2026): one renderer embedded everywhere instead of reconciling two. Today it is embedded in the manager `mgr1on1` page (rep views and the Snapshots section were removed Sep 11).
- Eligibility: reps with real recent sales (last 2 weeks) or upfront opted in; recipients from `rep_onboarding` emails; manager CC dropped (managers get the daily text). Reps resolved with `makeRepResolver(onboarding)` (last name + prefix/initial when surname unique) and `_name-aliases.js`. Unmatched sellers are listed for manual email entry.
- **Manager grouping must come from the team roster store** (`loadRoster` overlays `__bria_teams__` now; earlier `__sequifi_teams__`, Master and paste), never `rep_onboarding.manager_name` (gave wrong managers and made the owner rightly furious).
- **Ramp strip** (Oct 20 2026, section `ramp`, `buildRamp`/`rampHtml`, `RAMP` config, view `rep_ramp_weeks`): shows a new rep's worked-week ramp (4 worked weeks of 4+ days over 10 doors inside 8 calendar weeks) with placeholder pay amounts; hides 4 weeks after graduation or close. See pay-and-payroll.md.
- Since Oct 14 2026 the email's PRA, knocking dedupe (MAX per rep/day, not SUM), sub rule and close rate mirror the app (metric alignment); before that it summed sr_activity + timetrack rows and read `rep_flags.is_sub` only.
- Content: knocking grid per day (Day/Doors/Unq%/Cont/Sold/CR/1st/Last; gold ≥8 / green ≥4 / red 0 sold; red first >1pm, red last <9pm; AVG row) shown only for teams with knocking toggled on; deals by status for two weeks; install performance (Completed IR); funnel with rolling `FUNNEL_WEEKS=4`; nudges for past-due pending and cancels in 7 days; "This week's goal" from `goals`; upfront section (was a pre-grace stub that told yellow reps they were off; verify before sending). No coaching prose. Grow palette (page `#f2f2ec`, green `#178f3f`, black masthead with `icon.png`).
- Email Sold merges report + Bria per rep-day max. `mergeKnockingSources` must match the app's merge.
- Corporate recap: `buildCompanyStats` + `renderCompanyEmail`; by-manager table Manager | Reps | Sold (▲▼) | Per rep | Booking days (colour flipped) | Inst | Canc | IR; Standard deals only; projected IR model (see metrics-definitions.md).
