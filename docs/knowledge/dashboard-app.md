# GrowSales dashboard app (`GrowSales/index.html` + `GrowSales/api/`)

## What it is now (Oct 2026)

A corporate back-office data tool at https://growsales.vercel.app. Since Sep 11 2026 it is **corporate only**: reps and managers are meant to use Bria. Exceptions: scoped manager access codes (Sep 12), email+password login for leaders (Sep 16), and cancel-caller logins that only see the Callbacks page. See access-and-logins.md. It is **data only**: no tasks, to-dos or alert pages (Flags page, Ops task list and rail badge removed Sep 16 2026).

## Architecture traps (read before editing)

- `index.html` is one ~1.5 MB file (was 1.74 MB before Sep 11). Edit with exact string replacements only; never rewrite from a stale copy.
- **Scope trap:** nearly everything lives inside `bootDashboard()` (`renderWeeks`, `renderUpfront`, `DATA`, `esc`, `Df`, `openDealDrill`, `openModal`, ...). `fetchLiveData()` sits at true top scope and cannot see them. A bare call from the fetch layer throws a ReferenceError that the surrounding `try{ DATA._x = await sbFetch(...); fn(); }catch(e){ DATA._x=[] }` swallows, blanking data that fetched fine (network tab shows 200). Rules: keep fetch and apply/render in separate try blocks; reach render code only through `window.*` hooks (`window._weeksRefresh`, `_overviewRefresh`, `_coachRefresh`, `_repsRefresh`, `_dailyRefresh`, `window._grow.*`, `window.openDealDrill`, `window.growEsc`). Console probes also only see `window.*`. Code outside bootDashboard that does `typeof x==='function'` silently gets 'undefined' (bit `renderFunnels`, `renderSubsView`).
- Inline `on*` attributes run in global scope; anything they call must be assigned to `window` first (e.g. `window._mktSetPresale`).
- Global blocks that sit AFTER bootDashboard: CANCEL CALLBACKS (right before the startup line `if(window._cbCallerMode&&window._cbCallerMode())window._cbCallerBoot();else fetchLiveData();`), the Recruiting board. They must never assume `DATA` exists and carry their own helpers.
- `fetchLiveData` loads late tables (rep_flags, report_config, Bria, contacts) AFTER first paint; anything rendered from them needs a re-render hook at the end of fetchLiveData. `loadRepFlags()` lands after boot; renderKpis + renderKnockWeeks re-run after flags (Aug 21 fix). KPI cache tokens must include anything they depend on (`_REP_FLAGS`, `_SUBS_BY_WEEK`, `_repOnboarding` length, subs mode, manager lock).
- `Df(id,key)` accesses deal fields (`r`=rep, `m`=manager, `s`=status, `pd`=planned date...).
- html2canvas report images: template roots need `letter-spacing:0.3px;-webkit-text-size-adjust:100%` and a canvas-safe unquoted font stack `Helvetica Neue,Helvetica,Arial,sans-serif` (no `-apple-system`), or iOS Safari collapses word spaces. Templates are built in single-quoted JS strings: no apostrophes in the CSS.
- Quirks-mode tables don't inherit color; set color explicitly on ledger tables.
- Never `[].slice.call(aSet)`; use `Array.from`.
- PostgREST offset paging must order by a unique key (`id`, `bria_id`, `sequifi_id`); ordering by `sale_date` silently drops/duplicates rows across pages. Default cap 1000 rows.

## Loading and egress (Sep 2026)

- `fetchLiveData` is one parallel wave. Big tables (`deals`, `knocking`, `bria_deals`, `bria_sales_daily`, `knocking_isp`) use `sbFetchPaged` (4000-row pages ordered on PK, max 4 in flight, retry on 5xx) with a `cols` list. Anon statement timeout is ~3s; a select-all on deals took 2.5s and concurrent big selects returned 500/57014 and blanked prod. Never go back to select-all.
- Supabase free-plan egress overage notice Sep 29 2026 (keep under 5.5 GB; grace ends Oct 30 2026). Fix Sep 30: column trims (27 → 17 MB per load), `sbFetchCached` keeps the five big tables in IndexedDB (`growsales-cache`) and re-downloads only when `data_versions` moved (statement trigger `bump_data_version`, `api/data-versions.sql`); `bria_deals` starts at `BRIA_DEALS_FROM` (Jan 1 of the year 60 days back). Reading a new column means adding it to the fetchLiveData column list. A new cached table needs a `bump_version_<table>` trigger. Session-only sign-ins never cache; sign-out deletes the DB.
- No more `grow_imported_data` 10 MB localStorage cache; xlsx and leaflet script tags removed.

## Key pages and what drives them

- **Knocking board** (`renderKnockBoard`): rep/team/ISP views. Sold = Bria per rep-day (max with knocking row). Teams view grouped by market (`_kbTeamMarkets`: majority of reps' latest deal ISP+state in 21 days; Ezee by state MI Michigan, TX Houston, IL Chicago, NM Albuquerque; Sequifi tag only as fallback). ISPs view from `knocking_isp` + source-named feeds, shows "Ezee <market>" from `knocking.market`. Per-rep fresh-data stamps (`_kbFreshTag`). "Not out yet" strip. Publishes the Bria feed (`window._kbPublish`). Source filter chips derive from the rows. See knocking.md.
- **Sales by Week (Weeks):** Sold from Bria, Inst/Canc/IR/booking from the report, Reps = worked reps, Wkly PRA, Completed IR + Install Rate pair; subs lens (Combined/Internal/Subs, localStorage `growSubsMode`, default 'all') lives only here and drives every `growSubsPass` gate. Projection strip (SVG line). Reconciliation status column (`week_reconciliation`).
- **Payroll:** upfront pay (see pay-and-payroll.md).
- **KPIs:** see metrics-definitions.md.
- **Custom Report:** filter chips with popovers, presets in localStorage, CSV.
- **Install Slots** (key `installslots`, MGR_PAGES scope none): reads `install_slots_latest`; one card per ISP, pill green ≤3 days, amber ≤5, red above, 14-day strip. Bot: `scripts/install-slots.mjs` (adapters per ISP; `--isp/--market/--dry/--headed/--login`), probe doors `data/install-slot-probes.json` (must not be existing customers), table `install_slots` + view (`api/install-slots.sql`). TDS live (public offer portal, no customer info needed); Surf live (Retool portal, User ID + PIN in `.env.install-slots`, half-day windows); Lyte impossible (schedule after payment); SLIC now Inservio (`slic-m.inservioapp.com`); i3 behind Cisco VPN; Omni Pega/OmniSSO; Ezee/Bluepeak Opendoor/Atlas. Never run on a rep's Lyte QR. Runners are WolfOffice launchd jobs (see wolfoffice.md). Calling partner endpoints needs ISP buy-in.
- **ISP Maps:** see isp-pipeline.md.
- **Markets** (More > Analysis, `renderMarkets`, corp only): Weeks table by market = ISP + state; drill week > market > rep > deals, never a manager tier; same columns/formulas as Weeks; own includePresale checkbox; `MARKET_LABELS` renames; `_mktState` normalises PA/pa/Pennsylvania; current week seeded from Bria (`_mktSeedLive`, flagged "live thru", install cells shown as em dash). Known gap: settled-week Sold differs from Weeks (deals feed vs Bria).
- **Records:** All Reps leaderboard (`renderReps`/`_repGetRows`/`_briaYtdReps`, 351 reps / 19,019 YTD at Jul 23) and Leaderboard Club (`renderClub`, `copyClubReport`, `_clubBriaCounts`).
- **Rep Cards** (`renderFunnels`): rows are reps, funnel doors→contacts→sales, periods this/last/4wk/8wk/season, `openRepCard` + `#funCardBlock`. "Not on a team this week" panel sets `rep_flags.roster_status`.
- **Rep Read** `openRepRead(rep)`: pitch vs environment coaching card, peer-normalised (cancel ratio vs own areas ≥1.6× → pitch; early cancels ≤3d share ≥60% → remorse; booking days vs same-ISP peers ±1.5d).
- **Meeting** board + commitment grid: see meetings-and-decks.md.
- **Callbacks** (cancel call queue): sources (1) deals feed Cancelled rows callable 7 days after cancel within a 45-day window, (2) ISP cancel lists in `callback_leads` loaded by `scripts/callback-import.mjs` (cancel-list-import skill, dry run first; Lyte `lyte_cbi` profile uses name + sale date ±7d fallback). Keys `customer|sale_date|isp` lowercased (`_cbKeyOf` and `dealKey()` in the import script must stay identical) or `lead:<id>`. Tables `cancel_callbacks` (call log), `callback_assign`, `callback_leads`, `callback_pipeline` (kanban Working/Interested/Won/Dead, `api/callback-pipeline.sql`). Roles caller (own leads) and caller_lead (everyone's, Assign tab, Split evenly); `list_callers()` RPC. Outcome 'note' and 'text' never change queue state. Tap chaining after `tel:` (under 20s away → No answer first, longer → Saved first; sheet only if the page actually hid). A true auto dialer needs Twilio bridging. Search box, call-count filter, uncapped lists (Sep 29). ISP lists are the cancel truth (first Lyte list: 73 Grow sales, our feed called 68 Pending).
- **Recruiting** (`.rc-` namespace, outside bootDashboard): `api/recruits.sql` (`recruits` + `recruit_events`; stages new, contacted, interview, offer, hired, knocking, lost; no anon delete), `api/recruit-intake.js` (Meta Lead Ads webhook with signature check and `bodyParser:false`, keyed JSON for Zapier/Make, public `apply.html` form fenced to `form:'apply'`). Card border = contact clock (amber 5 min, red 15 min). Env `META_APP_SECRET`, `META_VERIFY_TOKEN`, `META_PAGE_TOKEN`, `RECRUIT_INTAKE_KEY`. Status: SQL/deploy were pending as of Sep 11.
- **Schedule** (More, key `teamsched`): public `schedule.html?team=<manager name>` rep form (time wheels, no sign in) saving only via `api/schedule.js` (service key; name must be on that team's roster, week this or next, Mountain time); tables `rep_schedules`, `team_roster`, `rep_checks` (`api/team-schedule.sql`). Roster = latest built week ≤ target in the team store + team_roster adds − hidden. Onboarding tab (Sequifi/Bria/first knock/first sale automatic; trainings tappable). Live Sep 16 2026.
- **Calculator** `calculator.html` (financial course companion, public, no network calls): see training-content.md.
- **Admin > Roster & subs**: paste roster / sub marks (`renderRosterAdmin`); **Admin > Access**: codes, perms, email users; **Admin > Reporting**: manager texts, knocking report picture (`openKnockText()`), copy company report.

## Serverless API (`GrowSales/api/`)

Crons on Vercel (UTC): `sequifi-sync` 08:30 (→ `rep_onboarding`), `sequifi-teams-sync` 08:45 (→ `__sequifi_teams__`), `bria-sync` 09:00, `sync-watchdog` 10:00 (stale >20h or errored → push via `api/_notify.js`), `weekly-summary` Mon 14:00. Pronto sync cron was 08:45 before its deletion. All manual triggers accept `?key=SYNC_TRIGGER_KEY` (`curl "https://growsales.vercel.app/api/<sync>?key=$SYNC_TRIGGER_KEY"`); `CRON_SECRET` is deliberately unreadable. Other endpoints: `weekly-rep-email.js`, `sheet-sync.js`, `auth.js`, `schedule.js`, `recruit-intake.js`, `_name-aliases.js` (shared alias map), `_notify.js`. Function ceiling 60s (Hobby).

## Known security limits

Codes and email login gate the UI only. The anon key ships in page source and every browser downloads all tables, so anyone can read data via console or curl. Still public: `/scripts/*`, `anon-key.txt`, `team-*.json` rosters; `/api/weekly-rep-email?snapshot=<rep>` is unauthenticated by design. Real fix = Supabase Auth + RLS / server-side filtered loads ("level 3"), not built.
