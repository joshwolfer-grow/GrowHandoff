# ISP pipeline: lead files, imports, workbooks, sector maps

Grow knocks doors for several fiber ISPs. Codes used in file and batch names: Lyte `LY-`, i3 `I3-`, SLIC `SLIC-`, Glo `GLO-`/`GL-`, GFiber (Google Fiber) `GFI-`, GigabitNow `GB-`/`GBN`, Surf `SURF-`, Northern Lights `NLF-`/`NL-`, Skynet `SKY-`, Omni. Others: Ezee (Houston/Chicago/Michigan/Albuquerque, knocking via Opendoor portal), Bluepeak, TDS (Madison WI, separate company), Cityside, T-Fiber (T-Mobile Fiber, new Sep 2026), Coastal Bend.

## Intake of an ISP lead file (isp-leads skill)

House rules: a person (Claude via the **isp-leads** skill) reviews every file; the watcher only archives and parks. ISPs change layouts between sends (split house numbers, units glued on, renamed city columns), so always show the headers and first rows before building, and report source / in-file dupes / already in SR / new / DROPPED / sold counts per sheet after. Counts must close: source = in-file dupes + already in SR + new + DROPPED.

- Drop folder `imports/isp/` (launchd `com.grow.isp-intake`, every 5 min, `isp-intake.py --archive-only`): detect ISP from name/folder or from which ISP's batches own the town in the file (Champaign → i3), archive raw to Drive `SalesRabbit Leads/<ISP>/Raw/<date> <name>`, park in `imports/isp/parked/`, notify.
- Build: `python3 scripts/isp-intake.py <file> --assign "<rep>"` runs `scripts/lead-import.py`, names the import `SR <CODE>-<TOWN> (<m d>).csv` (NLF: `(<m_d>) - <rep>`; Lyte uses the sector number when present; town code = majority city), writes **CSV only** (SalesRabbit's importer rejects xlsx, since Sep 9 2026) to `imports/isp/ready/` and the ISP's Drive `Imports/`. A `<name> - dupes.xlsx` review sheet (current stage/knocks/last knock) goes to `<ISP>/Raw/`. Zero new = no import file. No rep = parks.
- The SalesRabbit upload is still a manual browser click (Flatfile, no API).
- **Hand over the import csv only** (Oct 8 2026, Sterling Surf: "I just need the one file to upload"): send the one `SR <CODE>-<TOWN> (<m d>).csv`; the dupes report still gets filed to Drive `<ISP>/Raw/` but is not sent. Mention its Drive location only if relevant. Markdown links to `~/Grow/GrowSales` paths do not open from the Desktop session; hand files over as attachments.
- Files also arrive by mail: `com.grow.mail-leads` (every 10 min) pulls xlsx/csv attachments from Daxton's and Nick's mails into `imports/isp/` with a quoted `.ask.txt` sidecar of what they asked ("make a sheet for Will"). It never imports; the intake watcher then archives and parks as usual. On Oct 21 2026 17 files were sitting in `imports/isp/parked/`.
- **One workbook in = ONE import CSV**, even with several sheets/towns: stack sheets under one header, run once, name for the majority town and date (e.g. `SR LY-UVALD (9 17).csv`), still report per-sheet counts. Split only when asked (Sep 17 2026).
- **Existing customers go in the same import** as `Current Customer` (e.g. SLIC `Customer` yes/no column). `lead-import.py` auto-detects the flag column (`c_cust`, since Sep 15 2026); confirm the printed stage counts show Current Customer. (A split second file was never uploaded Sep 4 2026: 1,632 SLIC customer doors missing.)
- **Blank zips:** lead-import needs street + 5-digit zip for the dedupe key. It now prints a loud `DROPPED` block per town and `--fill-zip-from-city` recovers rows whose city has a zip elsewhere in the file. A town with no zip anywhere needs a human lookup (Sep 4 2026 lost Schroon Lake 532 and Paradox 210; Schroon's only zip was a typo 12970 = Saranac Lake).
- **Same-day name collision:** a second drop for the same town and day silently OVERWRITES the first (ready/ and Drive Imports/). Check first; rename e.g. `... (9 24) 2.csv`.
- Dedupe is against the crawl (`data/sr-doors-by-area.csv`), never a lead export. Check the crawl isn't dataless and has had deleted leads purged (see knocking.md).
- lead-import options: `--assign`, `--country`, `--status-from <col>`, `--notes-from <col>`, `--fill-zip-from-city`. Rep emails from `data/rep-emails.json` (grow-sync maintains it). Unit stripping needs a space or `#` before the unit (fixed Sep 11 2026: "COUNTY RD 3331" was becoming "COUNTY RD 333").

## Batch ownership (which ISP owns a door)

Every SR lead carries `import_id`. `scripts/isp-registry.mjs` pulls `GET /imports` (same auth as the crawl), labels batches by file-name prefix into `data/isp-imports.json`, `--label <id-prefix> <ISP>` for odd ones, exit 2 when a batch is unlabeled (daily runner turns it red). Six Kansas City batches loaded another way are hand-labelled GFiber. `scripts/isp_territory.py` (`Territory.isp_of`) is the single resolver for knock-export.py and knock-report.py: batch (97%) → zip majority (3%) → `data/isps.json` map → unassigned. Built Sep 8 2026 after Austin/Round Rock (GFiber inside Lyte's Texas) leaked. Fixed leaks: Skynet Tyler TX (1,933 doors) off Lyte; two i3 batches in Chesterfield/Ellisville MO (4,700) off GFiber. Omni Toledo (718) and Skynet get no workbook by choice. TDS has no import batches (old SalesRabbit).

## ISP-facing knocking workbooks

- `scripts/run-isp-export.sh` (launchd `com.grow.isp-export`, once a day after 7am; force `ISP_FORCE=1 bash scripts/run-isp-export.sh`; log `imports/done/isp-export.log`; stamp `imports/done/isp-export-last-run`; marker `__isp_export__` cadence daily). Order: `isp-registry` → `grow-sync.mjs --skip-crawl --full-csv --no-push` (~3 min, holds the crawl pid lock) → `knock-export.py --isp all --week` → TDS map crawl (15 min cap) → `sector-maps.py --all` (own `sector_maps` marker).
- Output: ONE continuous workbook per ISP, `Grow & <ISP> Knocking Data.xlsx`, a tab per week, rebuilt from scratch daily (the dated weekly packet `weekly_packet()` is no longer called). Summary formulas over Leads; sector table when sectors exist (`sectors_for()` falls back to city when a sector file covers under half). No "First Time" column on any ISP-facing sheet; unique-door counts are precomputed. Lyte `_skip` historically; 7 of 8 ISPs build. `"total_doors": true` (SLIC only) adds Total Doors + Doors Knocked Rate (total = every non-vacant SR door in the ISP's batches; deleted leads inflate it). `"sectors": "map"` (Surf) makes `map_sectors()` read `<ISP>-cut.json` + `osm-cache/<ISP>-doors.json` instead of `<ISP>.csv`.
- `_saved()` only reveals in Finder when stdout is a TTY.
- **Drive split guard:** on Sep 14 2026 two overlapping runs made Google Drive for desktop rename each SHARED workbook to "... 2.xlsx" (frozen) and treat the canonical name as a new unshared file; ISPs saw stale data for 8 days. `knock-export.py shared_file_ok()` refuses to save when a " 2" twin exists or the file's `com.google.drivefs.item-id#S` xattr differs from `data/isp-drive-ids.json`. i3's shared workbook Drive id is `1Em3jecmcQsW8nxoBv145empMQBa0KBXF`. Repair with `scripts/fix-drive-split.sh` (a human runs it; renames shared files). If an ISP says the workbook is stale, compare Drive ids before rebuilding.
- Pitch to ISPs: "we've juiced this area, give us new leads"; definitions tab included.

## Sector maps

Purpose: sectors are drawn by hand as SalesRabbit areas and named, to track when areas were last worked. Shapes must be traceable (owner rejected Voronoi edges and road-hugging rural tentacles).

- **Grow cut** (ISPs that send no sectors): `python3 scripts/sector-build.py <ISP> --extract` (doors + at-door knock dates + per-door `marks`), `python3 scripts/osm-fetch.py <ISP>` (OSM roads/rail/rivers cached in `data/osm-cache`), `--cut` (freezes `data/sectors/<ISP>-cut.json`), `--map`. Never re-cut casually. Unit = city block; rural blocks > 0.25 km² become one filled shape split by nearest house + 450 m closing. Sectors 100 to ~250 doors, cap 500. `--extend` cuts only loose leads (cluster 1.5 km, skip pockets under `EXTEND_MIN=40`), existing names/shapes never rewritten; a town continues after its top zone. `--reshape` (Sep 14 2026, SLIC) redraws outlines from whole OSM blocks; not fully idempotent, don't run casually; backup `data/sectors/backup-pre-reshape`. extend() calls reshape after cutting a new town. `OSM_TIMEOUT` 20 min.
- **Names:** town code + zone + sector in walking order, e.g. `MASS 1.1`, `MASS 1.2`, `MASS 2.1`. Town code ALWAYS 4 capitals (1 word first 4; 2 words 2+2 GLFA; 3 words 1+1+2 SGFA; 4+ initials; clash = first letter + consonants, Watertown WTRT). i3/Lyte names are the ISPs' own. SR areas drawn under old names need manual renames. sector-build.py deliberately does not write `data/sectors/SLIC.csv` (would add a sector table to SLIC's workbook; ask first).
- **ISP-sent sectors** (`data/sectors/<ISP>.csv`, via `sector-import.py`, which also reads Lyte's "Serving Area" column and Surf file names): `isp_cut()` rebuilds `<ISP>-cut.json` every run (concave hulls split by nearest door, zone = sector-name prefix); unlisted doors join the containing shape or "<Town> (no sector)" dashed grey.
- **Hybrid** (Surf): Grow cut kept at `data/sectors/Surf-grow-cut.json`; `grow_fallback()` gives doors without a Surf area their Grow sector; Grow sectors under 20 doors (`GROW_MIN`) fold into the nearest area; `extend_grow_cut()` swaps the grow cut in for extend and always swaps back. Any ISP with both `<ISP>.csv` and `<ISP>-grow-cut.json` gets this.
- **Publishing:** `python3 scripts/sector-maps.py i3 SLIC Surf` or `--all` (`PUBLISHED` list; Lyte was out until Oct 13 2026 because its sectors covered 1,950 of 42,844 doors; it is now in, see "Lyte map" below). `--no-extract`, `--no-upload`. It runs `refresh_inputs()` (isp-registry + grow-sync --skip-crawl --full-csv) first. Nightly order: osm-fetch (incremental) → `sector-build.py --extend` → map. Maps go to table `public.sector_maps` (isp, built, doors, source, payload jsonb), anon-readable; writes via RPC `sector_map_put(p_key,...)` with the key hashed in `sector_map_writer`; the plaintext key is `data/.sector-map-key` (gitignored, never in `scripts/` since build.sh publishes that folder). Data refresh needs no deploy; page changes do.
- **Viewer:** `maps/view.html` is GENERATED from `scripts/sector-map.html` by `write_viewer()`, which pattern-matches anchors in the template (the DATA/PTS/META consts, opening `<script>`, `map.fitBounds(bounds.pad(0.02));`, the closing `render();`, and the `<title>` blanked by regex). Edit the template, never view.html; tell sector-maps.py if anchors move. EMBED block posts rows to the app (`growSectors` up, `growGo` down, `growOpen` up).
- **App page** More/Ops > ISP Maps (corp only; managers excluded): full-bleed map with table below (by sector or town, csv, click flies to sector). Map layout from the "Area Map Layouts" design (layouts 2 + 9): slim bar (search, Rested/Ready/Last worked/Sold, Filters popover that REMOVES non-matching areas, What's new), click area = right detail panel + others faded + house dots coloured by days since knocked. Display shapes are `clean_shapes()` (convex hull per 800 m cluster, 45 m mitre pad, overlaps split by one straight line); the owner called block-following outlines "horrible". "Days since knocked" is the median door, so the list also carries "Knocked lately" (doors in last 4 weeks) and "Last knock". "Open now" = never knocked + rested 30+ days. Colours: one per sector, touching sectors never share. Plain-English labels; sector names stay as-is (typed into SR).
- **What's new chip** (Sep 24 2026): door `added` date = its import batch date (`data/isp-imports.json`, else earliest inserted_at); a drop = batches ≤2 days apart with ≥10 doors (`DROP_MIN`), last 8 kept (`DROP_KEEP`); NEW tag for areas a drop drew, "+N" dashed for old areas that gained doors. TDS has no batches so no chip. Needs an extract after a drop.
- **Lyte map (live Oct 13 2026, follows SalesRabbit exactly since Oct 14):** the owner asked for the Lyte map "in the same format Lyte uses". Lyte runs on serving areas (FDH `TXBYTWAC010.SA05`, said "Baytown 10.05") and a turf tracker (tab "MIKES TURF TRACKER - 6.9" in their "GROW Headcount File - Living Doc", archived to Lyte/Raw: bucket READY / WATCH / RESTING / NOT RELEASED, last worked, pass, go live, HHU, last vendor). `python3 scripts/lyte-areas.py "<headcount xlsx>"` rebuilds `data/sectors/Lyte.csv` (sector = "Town H.SS", extra `fdh` column) from every Lyte/Raw drop (FDH column, else sheet name, else file name) plus SR batches whose file name names one area, and writes `Lyte-turf.json`; no arg = reuse the last turf json; sector-maps.py runs it before every Lyte build. Town names come from the code's letters (RCLD Richland, STMN Streetman; `TOWN_FIX` for codes no drop has spelled). Then, **Oct 14 ("needs to follow salesrabbit exactly")**: `sector-maps.py sr_cut()` (ISPs in `SR_EXACT`) builds `Lyte-cut.json` from `GET /areas` (curl -g with `sr-auth.json`; cached `data/sectors/Lyte-sr-areas.json`): every SR area holding a Lyte door, outline as drawn, title as typed; bare-number titles ("7.07") become Lyte names via `lyte_namer` (town from the doors' city, FDH must be on the tracker) so the turf card attaches. **Only numbered areas count** (title is a serving-area number alone or after a town prefix: "1.01", "2.04 A", "Jeff 1.01"); rep areas ("Jeff 1", "Erik Juice", "Ben 10.4 7/28/26") and untitled areas are skipped. Overlaps are real (each area counts every door in its outline; a door's dot goes to the smallest area; big areas drawn first). Undrawn doors grey per town only if 10+ (`GREY_MIN`). `build_map` honours `exact` (no `clean_shapes` redraw, no `assign_new`). Result Oct 14: 115 areas, 31,957 doors inside, 14,060 grey (Beeville, Pittsburg, Lake Jackson, Navarro towns, Atlanta have few numbered drawings); two SR areas both titled "2.04B" in Beeville show as "Beeville 2.04B (2)". `Lyte.csv` now only feeds names/turf. Lyte's knocking workbook stays by city (`"sectors": "city"` on Lyte in isps.json, an opt-out in `sectors_for`). `isp_cut` changes for all ISPs that day: lone pins (<3 doors 3 km from anything) dropped, doors 0.3 deg off their area's middle go loose, loose bunches <5 within 400 m join the nearby area, `drop_strays` removes doors in a non-served state with <20 doors. `upload()` retries 3x (a 57014 statement timeout hit once). Backups `*.bak-pre-lyte-areas`, `*.bak-pre-sr-exact`. `ISP_MAPS_HIDDEN=[]` in index.html `renderIspMaps` hides a map if needed.
- **TDS map** (live Sep 15 2026, 99 sectors, 16,276 doors around Madison WI): `scripts/tds-sr-sync.mjs` reads TDS's OLD SalesRabbit (`capi.salesrabbit.com/v1`, GET `/v1/leads/<id>` for every lead id Amplify saw Grow knock; coords [lat,lon] stored as [lon,lat]) → `data/tds-leads.jsonl`, `tds-doors-by-area.csv`, `tds-activity.csv`. `--sweep` (all TDS leads via POST `/v1/markers`) is NOT wanted ("i just need the leads i have... only around madison"). ## SalesRabbit areas API

- Read `GET /areas?page[limit]=500&page[offset]=N` (attrs title, color, homes, group_id, tenant_id, coordinates as [lat,lng] rings, external_id, dg_ai_id, history); `GET /groups` = teams (nest via parent_id). No /territories, /teams or /users route.
- Move: `PATCH /areas/{id}` `{"data":{"type":"area","id":"<id>","attributes":{"group_id":"<gid>"}}}` (type singular; PUT not routed). An area's team does not follow its reps.
- Create: `POST /areas` with `{"data":{"type":"area","attributes":{title,color (hex, no #),tenant_id,group_id,coordinates:{type:"Polygon",coordinates:[[[lat,lng],...closed]]}}}}`; tenant_id required (Grow `ea339b66-e93a-432d-bdfc-f59bacb33ec4`, corporate group `26487a33-1850-4a75-b449-ff597fa37132`). Cut polys (`poly[0][0]`) are already [lat,lng]. Bulk: `scripts/sr-area-create.mjs <ISP> <prefix> [--apply]` (ids logged to `data/sectors/sr-areas-created.log`; first used for Surf BRAI 1.1 to 3.3). Team moves: `scripts/sr-area-group.mjs` (`--snapshot / --plan csv / --apply / --rollback`, dry by default; refuses to move the 326 corporate sector-named areas without `--include-corporate`).
- Of 1,809 areas: 326 corporate sector names, ~279 titled with a rep's first name, 1,204 blank. Match areas to doors by polygon against `data/sr-leads.jsonl` (leads GeoJSON [lng,lat]; swapped) and read assignee via `data/sr-lookups.json`.

## SalesRabbit duplicate cleanup

- Tool `scripts/dedupe-delete.mjs` (dry by default; `--go` deletes after re-checking each pair live; `--list <csv>`; `--near` = 60 m). SR delete is permanent: the human runs `--go`. Backups per run in `data/dedupe-backup-<date>/` (reimport.csv in SR import layout, activity.csv, leads-full.jsonl, remove-list.csv). Purge the crawl afterwards under the pid lock (originals `*.pre-purge-<date>`).
- Keep rule: stage rank first (Sold > Current Customer > ... > Not Home; New Lead copy removed first), latest activity only breaks ties.

Sep 22 2026: 107 near-pin Uvalde dupes removed.
